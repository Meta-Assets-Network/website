## 執行摘要

MA 鏈（MetaAssets，以下簡稱"MA 鏈"）提出一種面向"現實世界算力資產（RWA）"與"鏈上資產（MetaAssets）"統一確權、統一計量與統一激勵的區塊鏈基礎設施：通過 POCC（Proof of Computation Capacity，算力容量證明）把可審計、可託管、可租賃的真實算力裝置對映為鏈上 Capacity Unit（容量單元）資產；再以"算力容量 + 質押"構成共識權重，在 BFT 最終性框架下實現高吞吐、低能耗、可治理升級的公鏈/聯盟鏈混合架構。

該路線吸收了經典 PoW 在開放網路中的抗女巫與成本錨定思想，參照 PoS 在安全性與經濟激勵方面的形式化研究成果，並借鑑 PoC/Proof-of-Space 在資源佔用與能耗之間的折中邏輯、PoET/TEE 機制對低能耗隨機性與公平性的探索以及其已知攻擊面。

在治理層面，MA 鏈引入 TSS（門限簽名）作為"鏈上投票 + 鏈下門限簽署"的雙重執行控制：鏈上 Governor/Timelock 完成可驗證的提案與投票，關鍵升級與引數變更須經門限簽名共同背書，從而降低單點金鑰與單一執行者風險。

在資產化與合規方面，MA 鏈將裝置與收益權以 EIP-721 相容的 NFT 形式表達，並在"基金會監督 + 社群認可 + 挑戰期"流程下完成鑄造與狀態變更。

## 引言與背景

區塊鏈共識機制的核心矛盾可概括為：在開放或半開放網路中，如何以可度量的成本或可懲罰的抵押，抑制女巫攻擊、拜占庭作惡與審查，並在吞吐、最終性、能耗與去中心化之間取得可工程化的平衡。

比特幣提出的 PoW/Nakamoto 共識把安全性錨定在持續消耗的外部資源上，並以最長鏈規則在機率意義上收斂；但 PoW 的能耗與外部性長期飽受爭議。PoS 則將安全性錨定在可罰沒的內部資本，形成"以經濟懲罰替代能源消耗"的主流路線。

BFT 類共識（PBFT、Tendermint、HotStuff 等）通過在部分同步假設下提供確定性最終性與可問責性，成為高效能鏈與聯盟鏈的主幹。

在 PoW 與 PoS 之外，"資源證明"機制不斷演化：PoC/Proof-of-Space 用儲存資源替代計算資源；PoET/Proof-of-Luck 等 TEE 路線嘗試用可信硬體產生隨機等待或抽籤。

"RWA 資產上鍊（tokenisation）"則在金融與產業側推動了新敘事：權威機構將 tokenisation 定義為"在可程式設計平臺上生成並記錄傳統資產的數字表示"的過程。

在上述背景下，MA 鏈的研究命題是：能否把"現實可審計的算力資產"轉化為鏈上可組合、可治理的 MetaAssets，並用其"容量"形成新的共識權重與經濟激勵。

## 設計目標與關鍵假設

MA 鏈的目標可分為六類：

1. **安全性與可問責性**：在拜占庭環境中提供可證明的安全邊界，並具備可審計的作惡證據與懲罰機制。
2. **低能耗與高吞吐**：避免 PoW 的持續能源消耗外部性，並儘可能採用 BFT 最終性減少重組成本。
3. **算力資產化閉環**：從購入、託管、計量、租賃、收益分配到撤銷處置，全流程可審計、可治理。
4. **治理可升級**：核心"算力合約"與關鍵引數支援鏈上投票升級，並通過門限簽名提供執行層的去單點化控制。
5. **可組合的合約與資產標準**：儘量複用 EIP-721、EIP-712 等生態工具，實現跨錢包、跨工具鏈的相容性。
6. **合規可配置**：在不同司法轄區下以模組化方式實現 KYC/AML、資料隱私與 RWA 託管結構適配。

## 系統架構

MA 鏈採用"鏈上可驗證狀態機 + 鏈下可審計計量與門限簽署"的分層架構。

該思路與"鏈下收集觀測—鏈上提交聚合報告"的預言機範式一致。

裝置側"遠端證明"是可選但強建議的安全增強。

## POCC 共識機制與 TSS 驅動治理

POCC 的核心思想是把"可審計的算力容量"作為一種長期資源承諾，並將其抽象為鏈上 Capacity Unit（CU）資產。

與 PoW 的"持續消耗型成本"不同，POCC 更接近"佔用/可用型資源證明"；與純 PoS 的"資本承諾"不同，POCC 額外引入"現實裝置與服務交付能力"的錨定。

### POCC 的協議原語與流程

為把 POCC 落地為可工程實現的共識機制，本文建議把"共識最終性"與"權重來源"解耦。

1. **容量承諾**：裝置通過"證明材料 + 測量結果"獲得 CU；CU 的有效性與狀態變更由鏈上合約管理。
2. **權重計算**：每個驗證者在紀元 e 的共識權重建議定義為 W = f(Stake, CU, Uptime, SlashingHistory)。
3. **提議者抽樣**：建議採用可驗證隨機函式（VRF）在權重分佈上抽樣提議者。
4. **BFT 最終性**：採用 HotStuff/Tendermint 類兩/三階段投票，達到 2f+1 投票則最終確認。

### 紀元生命週期（概念級虛擬碼）

<CodeBlock language="pseudocode" title="紀元生命週期">{`// Epoch e lifecycle
OnEpochStart(e):
    seed_e <- Hash(block_{e-1}.finalized_root)
    committee_e <- SelectValidatorsByWeight(W_{e-1}, seed_e)
    Publish(committee_e, seed_e)

DuringEpoch(e):
    for each round r:
        proposer <- VRF_Sample(committee_e, W_e, seed_e, r)
        block <- proposer.BuildBlock(mempool)
        votes <- BFT_Vote(block, committee_e)
        if votes >= 2f+1:
            Finalize(block)

OnEpochEnd(e):
    receipt_root <- OffchainAggregateComputeReceipts(e)
    sig <- TSS_Sign(receipt_root, committee_e)
    SubmitOnchain(receipt_root, sig)
    UpdateWeights(W_{e+1})`}</CodeBlock>

### TSS 驅動的鏈上治理、算力合約升級與引數變更投票流程

MA 鏈治理建議採用"鏈上可驗證決策 + 門限簽名執行授權 + Timelock 延遲"的三段式控制面：

- **鏈上決策**：基於 Governor 合約實現提案、投票、計票、通過與佇列。
- **門限簽名執行授權**：關鍵操作在鏈上通過後，仍需由 TSS 委員會對"提案雜湊/執行雜湊"進行門限簽署。
- **Timelock 與挑戰期**：即使門限簽名完成，仍建議在鏈上 Timelock 中排隊。

建議的鏈上治理執行訊息採用 EIP-712 結構化簽名，避免"簽名內容不可讀"引發的操作風險。

## 容量單元與 RWA/NFT 生命週期

### 容量單元定義

Capacity Unit（CU）的定義必須同時滿足：可計量、可審計、可升級、可與收益權繫結。

CU 的最小表達形式是 EIP-721 相容 NFT：每個 CU-NFT 對應一臺裝置或一組裝置在某一有效期內的容量承諾。

在更強的可用性與組合性需求下，CU 也可擴展為 ERC-3525/1155 等"半同質化"或"多資產"標準。

### CU 鑄造流程：基金會監督與社群認可

鑑於 RWA 的本質風險在於"鏈上 token 與鏈下權利/資產之間的可執行性斷裂"，CU 的鑄造需要引入"監督 + 認可 + 可挑戰"的制度化流程：

1. **申請與材料提交**：裝置所有方/礦池提交購置憑證、序列號雜湊、託管協議等。
2. **託管與登記**：由 MA 基金會對裝置進行託管登記，形成"可追溯的佔有與控制鏈"。
3. **計量與驗證**：鏈下驗證者執行基準測試與線上率觀測。
4. **社群審議與挑戰期**：在鏈上釋出"待鑄造 CU 提案"，開放挑戰期。
5. **監督簽署與鑄造**：挑戰期結束且無有效異議後，由 TSS 委員會門限簽名並鑄造 CU-NFT。
6. **持續監督與狀態維護**：裝置線上率、韌體狀態與託管狀態變化應觸發 CU 狀態更新。

### 裝置到 RWA 的生命週期

裝置生命週期建議定義為狀態機，推薦狀態包括：

<Callout>*Purchased → Custodied → Listed → Contributing → Suspended → Revoked → Retired*</Callout>

觸發條件應儘量客觀化：託管簽收記錄、線上率閾值、租賃合約狀態、審計結論或仲裁裁定等。

## 節點與礦池模型、經濟激勵

MA 鏈建議把網路參與者劃分為三類角色：驗證者、礦工/算力提供者、礦池/運營商。

### 質押與部署

驗證者同時要求兩類抵押：原生代幣質押（可罰沒）與 CU 的繫結或委託，形成"雙資源錨定"。

### 算力記錄與上鍊摘要

算力記錄的難點在於：鏈上無法高頻驗證大規模計算明細。因此建議採用"三層證據"：

1. **裝置側簽名/證明**：裝置對任務執行摘要簽名。
2. **礦池聚合與異常檢測**：礦池聚合多裝置日誌，執行統計檢測與挑戰響應。
3. **TSS 報告背書**：由獨立的 TSS 委員會對"紀元結算根"門限簽名。

### 經濟模型與激勵

- **區塊獎勵與交易費**：分配給驗證者與 CU 持有者。
- **算力租賃收入**：租賃端支付租金進入結算合約；礦池按任務完成度與 SLA 分配。
- **罰沒**：至少分三層：共識層、計量層、RWA 層。
- **流動性設計**：CU-NFT 的流動性與"現實託管/監管要求"存在張力。

## 安全性、合規與運維路線

### 安全性分析

MA 鏈若採用 BFT 最終性，其安全性邊界通常落在"委員會中拜占庭節點數 f < n/3"條件上。

### POCC 特有攻擊面

- **虛假算力/虛假託管**：用偽造證明材料獲取 CU；需要挑戰期、抽檢與門限簽署降低風險。
- **算力測量操縱**：基準測試可被針對性最佳化或作弊，建議採用多樣化測試集。
- **礦池集中化**：礦池聚合可能形成權力中心；應在權重函式中對單一運營商設定上限。
- **TEE/遠端證明風險**：若 POCC 強依賴 TEE/SGX，則必須繼承其已知攻擊面。
- **TSS 安全與金鑰管理風險**：門限簽名降低了單點洩漏風險，但引入了 DKG、輪換等複雜性。

### 合規與法律風險

1. **RWA 權利對映與託管**：tokenisation 只是數字表示，資產權利的可執行性仍取決於合同與託管安排。
2. **虛擬資產 AML/CFT**：若 MA 鏈的代幣構成虛擬資產或 VASP 範疇，則需遵循 FATF 建議 15。
3. **市場完整性與投資者保護**：IOSCO 對加密市場的政策建議強調了市場操縱與披露等監管關注點。
